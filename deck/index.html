BMad + OpenSpec · a 15-minute tour

Plan it with BMad.Change it with OpenSpec.

Two open-source methods that give AI coding agents a plan to follow and a spec to keep.

BMad = what to build

Agents, PRD, architecture, stories

OpenSpec = how it changes

Proposals, spec deltas, tasks, archive
The problem

AI coding without a plan drifts, because intent lives in chat and disappears

Requirements hide in a chat thread

Scroll back to find what we agreed.

Every new session starts from zero

The agent forgets yesterday's decisions.

Decisions stay invisible until the diff

Reviewers see code, not the reasoning.
The fix: write the plan down, in files that both the team and the agent read.
The big picture

BMad decides what to build. OpenSpec records how the system changes.

BMad · the planning layer

  • Specialist agents: analyst, PM, UX, architect, developer
  • Produces: brief, PRD, architecture, epics and stories

OpenSpec · the change layer

  • Every edit is a proposal: why, what, how, tasks
  • Produces: a living spec of what the system does today

Why we are doing this and what changes

design.md
How we will build it (optional)
tasks.md
The checklist the agent works through
OpenSpec · the loop

Propose, apply, archive: three commands carry a change to the finish

1
/opsx:propose
Writes proposal, spec delta, design and tasks. No code yet: you review the plan.
2
/opsx:apply
Implements the tasks one by one and ticks them off.
3
/opsx:archive
Merges the spec delta into the living specs and files the change away.
Not sure yet? /opsx:explore is a thinking partner before you commit.

Worked example · 1 of 3

BMad turns “export my notes” into a story with acceptance criteria

Story 1.1
As a note-taker, I want to export a note as a PDF, so I can share it outside the app.
  • AC1 An Export button appears on every open note
  • AC2 The PDF keeps the title, body, and images
  • AC3 An empty note shows a friendly message, not a blank file
Produced with /bmad-prd/bmad-architecture/bmad-create-epics-and-stories
Worked example · 2 of 3

OpenSpec turns that story into a reviewable change with testable scenarios

/opsx:propose add-pdf-export→ writes proposal, design, tasks and this spec delta
## ADDED Requirements
### Requirement: Export note as PDF
The system SHALL let users export a note as PDF.
#### Scenario: Export a populated note
- WHEN the user chooses Export as PDF
- THEN a PDF with title, body and images downloads
#### Scenario: Export an empty note
- WHEN the note has no content
- THEN the user sees “Nothing to export yet”
Each acceptance criterion from the story became a WHEN / THEN scenario.
Worked example · 3 of 3

Apply builds it; archive folds it into the living spec

/opsx:applyworks through tasks.md
[ ][x] 1.1 Add an Export button to the note toolbar
[ ][x] 1.2 Render title, body and images to PDF
[ ][x] 1.3 Show a message for empty notes
/opsx:archivemerges and files away
+ openspec/specs/note-export/spec.md
→ openspec/changes/archive/YYYY-MM-DD-add-pdf-export/
Choosing

Use both for big work; use OpenSpec alone for small, well-understood changes

New product or big feature

BMad then OpenSpec
Plan with the agents, then one change per story.

Small feature or bug fix

OpenSpec only
Run /opsx:propose and skip the planning phase.

Direction changed mid-build

Re-plan
/bmad-correct-course, then /opsx:update to revise the change.

OpenSpec · how to call it

Inside your AI agent, six /opsx: commands cover the whole loop

Prefer words? Say “openspec propose”. The matching skills respond too.
/opsx:explore
Think it through before committing
/opsx:propose <idea>
Create all planning files in one step
/opsx:update
Revise a change plan, keep the files coherent
/opsx:apply
Implement the tasks
/opsx:sync
Merge spec deltas without archiving
/opsx:archive
Finish: merge and file the change away
OpenSpec · how to call it

In your terminal, the openspec CLI shows where every change stands

openspec init
Set OpenSpec up in a project
openspec list
Active changes (add --specs for specs)
openspec status --change <name>
Which artifacts are done
openspec show <item>
Read a change or spec
openspec validate
Check changes and specs
openspec view
Interactive dashboard
openspec archive <name>
Archive a finished change
openspec update
Refresh generated instruction files
Together · step by step

The handoff is six steps you repeat for every story

1
Pick the next story from _bmad-output/planning-artifacts/
2
Run /opsx:propose <story-name> with the story, its criteria, and architecture notes
3
Review proposal, spec delta, design and tasks. Edit until right
4
Run /opsx:apply to implement the tasks
5
Run /opsx:archive to merge the spec delta
6
Update sprint status, then run /bmad-code-review
